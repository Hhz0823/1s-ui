# 1S-UI 安卓监控 App

用手机集中查看所有面板的服务器：在线情况、CPU、内存、磁盘、网络速度、流量、负载、延迟和历史曲线；查看每台服务器的节点；测手机或另一台服务器到服务器的 TCP / UDP 速度和延迟；监测 SOCKS5 / HTTP 代理和各协议节点是否可用；查看和切换飞牛 NAS、OpenWrt 等客户端设备的代理。App 可以在后台定时检查，服务器离线、恢复、资源过高或代理 / 节点不可用时发通知，并会检查 App 和面板的新版本。

## 功能

- **首页（服务器）**：绑定多个面板时，默认把所有面板的服务器合并显示（Komari 风格卡片）；顶部标题可切换「全部面板」或某一个面板，可按面板、分组、在线状态筛选和搜索。某个面板连不上时只在列表上方提示，其他面板照常显示。
- **服务器详情**
  - 概览：实时状态、CPU / 内存 / 网速 / 磁盘历史曲线、与面板的延迟、系统信息。
  - 节点：每个入站的协议、端口、TLS / REALITY、传输方式、VLESS Encryption、CDN、用户数、实时网速、累计流量和本月流量；「测延迟」从手机 TCP 连接每个端口（Hysteria2、TUIC 等 UDP 协议不适用）。节点信息不含密码、UUID、密钥和分享链接。
  - 测速：TCP 延迟、UDP 延迟（丢包、抖动）、TCP 下载 / 上传（1、4、8 条并发连接）、UDP 下载 / 上传（10～500 Mbps 发送速率，显示实际速率、丢包和抖动）。每项 5、10 或 15 秒。「从哪里测」可以选手机，也可以选同一面板下的另一台服务器（主控或家里的飞牛 NAS、OpenWrt 等中转端），测它到这台服务器的线路。
  - 客户端代理：这台服务器装的 1S-UI 可以当代理客户端时，概览页有「打开客户端代理」。
- **客户端（客户端代理）**：列出所有能当代理客户端的设备（主控本机，以及更新到新版本的子服务器、飞牛 NAS、OpenWrt 软路由），显示代理是否开启、分流模式、当前节点和延迟。进入设备可以开关代理、切换「绕过大陆 / 仅 GFW 列表 / 全局」、选择节点或改为自动选最快、全部测延迟（由设备自己测，反映家里网络的情况）、更新订阅、检测出口 IP；订阅显示已用流量、总流量和到期时间。订阅地址和代理端口密码不会发到手机。
- **监测**：SOCKS5 / HTTP 代理和各协议节点。列表显示每个监测的状态、延迟、最近 30 次检测、24 小时可用率和出口 IP；详情页有 1 小时到 3 天的延迟曲线、失败记录和出口 IP 变化；可以添加、修改、暂停、删除和立即检测。添加时有三种方式：
  - SOCKS5 / HTTP 代理：粘贴 `socks5://用户:密码@IP:端口`、`http://…`、v2rayN 的 `socks://` 链接或 `IP:端口:用户名:密码`。
  - 节点链接：粘贴 `vless://`、`vmess://`、`trojan://`、`ss://`、`hy2://`、`tuic://`、`anytls://` 或 naive 分享链接。链接只保存在面板，之后不再发到手机。
  - 服务器上的节点：选择服务器和它的入站，面板自己读取链接，节点改了端口或密码也会自动跟上。

  都可以选择由主控还是哪台子服务器检测；选家里的飞牛 NAS 或 OpenWrt，就能看到节点在家里的网络下能不能用。
- **后台通知**：服务器离线 / 恢复、CPU / 内存 / 磁盘超过阈值、代理或节点不可用 / 恢复。
- **检查更新**：打开 App 时（每 6 小时最多一次）检查 GitHub 上的最新版本，有新版时首页提示，可直接下载或经加速镜像下载 APK；GitHub 的接口连不上时改用发布页跳转和加速镜像。「设置 → 已绑定的面板」显示每个面板的版本，服务器卡片上的「可更新」表示它的面板落后于最新版本。

## 绑定面板

1. 在面板打开「设置 → 前端与后端」，找到「手机监控 App」，点「生成密钥」。
2. 在 App 里点「扫码绑定」扫描面板显示的二维码；也可以在面板复制绑定码后点「粘贴绑定码」，或手动填写面板地址和监控密钥。
3. 可以绑定多个面板；绑定第二个面板后首页自动切到「全部面板」。

监控密钥只能访问 `/apiv2/monitor/*`：查看服务器状态、节点摘要和客户端代理状态；默认还可以管理监测、发起测速和管理客户端代理（切换节点和模式、测延迟、更新订阅），这三项可在面板「手机监控 App」卡片里分别关闭。密钥不能登录面板、不能读取节点密码和密钥、不能修改节点或执行命令。密钥只在生成时显示一次，面板只保存它的哈希；重新生成或停用后，旧密钥立即失效。

面板地址填写浏览器里打开面板的地址即可，例如 `http://1.2.3.4:2095/` 或 `https://panel.example.com/app/`。没有写 `http://` 或 `https://` 时按 `http://` 处理。HTTPS 面板使用自签证书时，App 会显示证书指纹，确认后固定信任这张证书；证书变化后 App 会拒绝连接，需要解绑后重新绑定。

## 测速

测速时 App 先请面板（或经面板请子服务器）开一个测速会话：服务器在测速端口（默认 5201，可在面板「手机监控 App」卡片修改，子服务器也用这个端口）同时监听 TCP 和 UDP，只回应持有本次令牌的客户端；会话 2 分钟内可以开始测试，测完自动关闭端口。

- 需要在服务器防火墙和云服务商安全组放行测速端口的 **TCP 和 UDP**；连不上时 App 会提示试过的地址和端口。
- App 依次尝试服务器的公网地址（子服务器的「公网地址」、连接主控时的 IP、网卡地址），最后才是内网地址；主控本机优先用绑定时的面板地址。
- UDP 下载会持续给手机发包，只要手机每 0.2 秒回一次心跳；心跳停止 1 秒后服务器立即停发，所以别人无法借测速端口向第三方发流量。

## 中转测速

在服务器详情「测速」里把「从哪里测」选成另一台服务器后，App 请面板让那台服务器（主控本机或子服务器）对这台服务器跑同样的测试，App 每秒读取一次进度和结果。发起测速的服务器需要更新到支持中转测速的版本；两台服务器同一时间只能有一个测速。

## 监测

代理和节点监测保存在面板上，由面板按间隔（30 秒～1 小时）检测，App 关闭时也照常记录，结果保留 3 天。

- **由谁检测**：「主控本机」或任一在线的子服务器。只允许中转服务器 IP 连接的落地代理，就选那台中转服务器；子服务器需要更新到支持代理检测的版本（面板会提示）。
- **怎么检测**：连接代理 → 登录（有用户名时）→ 通过代理建立到测试网址的隧道 → TLS 握手 → 读取响应。默认测试网址是 Cloudflare 的 trace 页面，同时得到出口 IP 和国家。
- **节点怎么检测**：检测服务器临时用节点的配置建一个 sing-box 出站，经节点访问测试网址；分别记录连接节点、握手（TLS / REALITY / QUIC）和访问测试网址的耗时。
- **失败原因**：连不上（拒绝 / 超时）、认证失败、代理类型不对（例如把 HTTP 代理当成 SOCKS5）、代理拒绝连接目标、节点握手失败、节点没有转发（UUID / 密码不对或被干扰）、TLS 失败或测试网址无响应。检测服务器离线或版本过旧时记为「无法检测」，不算不可用。
- 检测不会连接回环、链路本地（含云厂商元数据地址）、组播等地址；内网地址可以检测。

## 数据接口

请求头带 `X-Monitor-Key: <密钥>` 或 `Authorization: Bearer <密钥>`。

| 接口 | 说明 |
| --- | --- |
| `GET /apiv2/monitor/servers` | 主控本机和所有子服务器的实时状态，以及面板支持的功能（`features`） |
| `GET /apiv2/monitor/servers/:id` | 单台服务器详情和历史，`id=0` 为主控本机 |
| `GET /apiv2/monitor/servers/:id/nodes` | 服务器的节点摘要和流量（不含密码和密钥） |
| `POST /apiv2/monitor/servers/:id/speedtest` | 打开测速会话，返回端口、令牌和可尝试的地址 |
| `POST /apiv2/monitor/servers/:id/speedtest/relay` | 从另一台服务器测到这台（`relay_id`、`tests`、`seconds`、`streams`、`udp_mbps`），返回任务 |
| `GET /apiv2/monitor/speedtests/:job` | 中转测速任务的进度和结果 |
| `GET /apiv2/monitor/servers/:id/client` | 设备的客户端代理状态：设置、节点、订阅（订阅地址只保留域名） |
| `POST /apiv2/monitor/servers/:id/client` | 客户端操作：`exit`、`select`、`test`、`subscription.update`、`mode` |
| `GET /apiv2/monitor/proxies` | 代理监测列表、状态和最近检测 |
| `GET /apiv2/monitor/proxies/:id?range=秒` | 单个代理监测的历史、失败记录和出口 IP |
| `POST /apiv2/monitor/proxies` | 添加或修改监测（`password` 为 `null` 时保留原密码；可传 `link`，或用 `node_server_id` + `node_inbound_id` 选服务器上的节点） |
| `POST /apiv2/monitor/proxies/test` | 只检测一次、不保存 |
| `POST /apiv2/monitor/proxies/:id/check` | 立即检测并记录 |
| `POST /apiv2/monitor/proxies/:id/delete` | 删除代理监测和它的记录 |

面板关闭了对应权限时，管理监测、测速和客户端代理的接口返回 HTTP 403。

## 构建

需要 JDK 17 和 Android SDK（compileSdk 35）。

```bash
cd android
./gradlew testDebugUnitTest assembleRelease
```

界面状态和逻辑在 `data/MonitorController.kt`，不依赖 Android，可以直接用 JUnit 测试；测速客户端 `data/SpeedTest.kt` 实现面板 `backend/speedtest` 的协议。

GitHub Actions 的「Android 监控 App」工作流会在修改 `android/` 时构建 APK；发布版本时 APK 会作为 `1s-ui-monitor-android.apk` 附在 Release 上。

要让每次发布的 APK 能直接覆盖升级，需要在仓库 Secrets 里配置固定的签名密钥：

| Secret | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 release.jks` 的输出 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 密码 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |
| `ANDROID_KEY_PASSWORD` | 密钥密码 |

没有配置时 APK 使用调试签名，可以安装使用，但不同构建之间不能覆盖升级，需要先卸载旧版。
