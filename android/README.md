# 1S-UI 安卓监控 App

用手机集中查看所有面板的服务器：在线情况、CPU、内存、磁盘、网络速度、流量、负载、延迟和历史曲线；查看每台服务器的节点；测手机到服务器的 TCP / UDP 速度和延迟；监测 SOCKS5 / HTTP 代理是否可用。App 可以在后台定时检查，服务器离线、恢复、资源过高或代理不可用时发通知。

## 功能

- **首页（服务器）**：绑定多个面板时，默认把所有面板的服务器合并显示（Komari 风格卡片）；顶部标题可切换「全部面板」或某一个面板，可按面板、分组、在线状态筛选和搜索。某个面板连不上时只在列表上方提示，其他面板照常显示。
- **服务器详情**
  - 概览：实时状态、CPU / 内存 / 网速 / 磁盘历史曲线、与面板的延迟、系统信息。
  - 节点：每个入站的协议、端口、TLS / REALITY、传输方式、VLESS Encryption、CDN、用户数、实时网速、累计流量和本月流量；「测延迟」从手机 TCP 连接每个端口（Hysteria2、TUIC 等 UDP 协议不适用）。节点信息不含密码、UUID、密钥和分享链接。
  - 测速：TCP 延迟、UDP 延迟（丢包、抖动）、TCP 下载 / 上传（1、4、8 条并发连接）、UDP 下载 / 上传（10～500 Mbps 发送速率，显示实际速率、丢包和抖动）。每项 5、10 或 15 秒。
- **代理监测**：列表显示每个代理的状态、延迟、最近 30 次检测、24 小时可用率和出口 IP；详情页有 1 小时到 3 天的延迟曲线、失败记录和出口 IP 变化；可以添加、修改、暂停、删除和立即检测。添加时可直接粘贴 `socks5://用户:密码@IP:端口`、`http://…`、v2rayN 的 `socks://` 链接或 `IP:端口:用户名:密码`，并选择由主控还是哪台子服务器检测。
- **后台通知**：服务器离线 / 恢复、CPU / 内存 / 磁盘超过阈值、代理不可用 / 恢复。

## 绑定面板

1. 在面板打开「设置 → 前端与后端」，找到「手机监控 App」，点「生成密钥」。
2. 在 App 里点「扫码绑定」扫描面板显示的二维码；也可以在面板复制绑定码后点「粘贴绑定码」，或手动填写面板地址和监控密钥。
3. 可以绑定多个面板；绑定第二个面板后首页自动切到「全部面板」。

监控密钥只能访问 `/apiv2/monitor/*`：查看服务器状态和节点摘要；默认还可以管理代理监测和发起测速，这两项可在面板「手机监控 App」卡片里分别关闭。密钥不能登录面板、不能读取节点密码和密钥、不能修改节点或执行命令。密钥只在生成时显示一次，面板只保存它的哈希；重新生成或停用后，旧密钥立即失效。

面板地址填写浏览器里打开面板的地址即可，例如 `http://1.2.3.4:2095/` 或 `https://panel.example.com/app/`。没有写 `http://` 或 `https://` 时按 `http://` 处理。HTTPS 面板使用自签证书时，App 会显示证书指纹，确认后固定信任这张证书；证书变化后 App 会拒绝连接，需要解绑后重新绑定。

## 测速

测速时 App 先请面板（或经面板请子服务器）开一个测速会话：服务器在测速端口（默认 5201，可在面板「手机监控 App」卡片修改，子服务器也用这个端口）同时监听 TCP 和 UDP，只回应持有本次令牌的客户端；会话 2 分钟内可以开始测试，测完自动关闭端口。

- 需要在服务器防火墙和云服务商安全组放行测速端口的 **TCP 和 UDP**；连不上时 App 会提示试过的地址和端口。
- App 依次尝试服务器的公网地址（子服务器的「公网地址」、连接主控时的 IP、网卡地址），最后才是内网地址；主控本机优先用绑定时的面板地址。
- UDP 下载会持续给手机发包，只要手机每 0.2 秒回一次心跳；心跳停止 1 秒后服务器立即停发，所以别人无法借测速端口向第三方发流量。

## 代理监测

代理监测保存在面板上，由面板按间隔（30 秒～1 小时）检测，App 关闭时也照常记录，结果保留 3 天。

- **由谁检测**：「主控本机」或任一在线的子服务器。只允许中转服务器 IP 连接的落地代理，就选那台中转服务器；子服务器需要更新到支持代理检测的版本（面板会提示）。
- **怎么检测**：连接代理 → 登录（有用户名时）→ 通过代理建立到测试网址的隧道 → TLS 握手 → 读取响应。默认测试网址是 Cloudflare 的 trace 页面，同时得到出口 IP 和国家。
- **失败原因**：连不上（拒绝 / 超时）、认证失败、代理类型不对（例如把 HTTP 代理当成 SOCKS5）、代理拒绝连接目标、TLS 失败或测试网址无响应。检测服务器离线时记为「无法检测」，不算代理不可用。
- 检测不会连接回环、链路本地（含云厂商元数据地址）、组播等地址；内网地址可以检测。

## 数据接口

请求头带 `X-Monitor-Key: <密钥>` 或 `Authorization: Bearer <密钥>`。

| 接口 | 说明 |
| --- | --- |
| `GET /apiv2/monitor/servers` | 主控本机和所有子服务器的实时状态，以及面板支持的功能（`features`） |
| `GET /apiv2/monitor/servers/:id` | 单台服务器详情和历史，`id=0` 为主控本机 |
| `GET /apiv2/monitor/servers/:id/nodes` | 服务器的节点摘要和流量（不含密码和密钥） |
| `POST /apiv2/monitor/servers/:id/speedtest` | 打开测速会话，返回端口、令牌和可尝试的地址 |
| `GET /apiv2/monitor/proxies` | 代理监测列表、状态和最近检测 |
| `GET /apiv2/monitor/proxies/:id?range=秒` | 单个代理监测的历史、失败记录和出口 IP |
| `POST /apiv2/monitor/proxies` | 添加或修改代理监测（`password` 为 `null` 时保留原密码；可传 `link`） |
| `POST /apiv2/monitor/proxies/test` | 只检测一次、不保存 |
| `POST /apiv2/monitor/proxies/:id/check` | 立即检测并记录 |
| `POST /apiv2/monitor/proxies/:id/delete` | 删除代理监测和它的记录 |

面板关闭了对应权限时，管理代理监测和测速的接口返回 HTTP 403。

## 构建

需要 JDK 17 和 Android SDK（compileSdk 35）。

```bash
cd android
./gradlew testDebugUnitTest assembleRelease
```

界面状态和逻辑在 `data/MonitorController.kt`，不依赖 Android，可以直接用 JUnit 测试；测速客户端 `data/SpeedTest.kt` 实现面板 `backend/speedtest` 的协议。

GitHub Actions 的「Android 监控 App」工作流会在修改 `android/` 时构建 APK；发布版本时 APK 会作为 `1s-ui-monitor-android.apk` 附在 Release 上。

要让每次发布的 APK 能直接覆盖升级，需要在仓库 Secrets 里配置固定的签名密钥：

| Secret | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 release.jks` 的输出 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 密码 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |
| `ANDROID_KEY_PASSWORD` | 密钥密码 |

没有配置时 APK 使用调试签名，可以安装使用，但不同构建之间不能覆盖升级，需要先卸载旧版。
